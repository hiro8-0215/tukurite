# AI仕上げの失敗を修正

2026-10-23。公開先：https://tsukurite-kitchen.expo.app/

## 確認したこと

利用者の画像では、自作レシピの仕上げ操作に、外部取り込み用の「本文や画像を追加してください」が表示されていました。

サーバーには同時刻の失敗が2件ありましたが、従来の処理は原因を記録していませんでした。画像で見えるタコ・グリル野菜・パスタに合わせた検証用レシピでは、Gemini 3.6 Flashが503を返し、同じ問題を再現しました。検証分を含め、従来のアプリ共通20試行/直近24時間にも達しました。元の利用者の失敗2件が同じ503だったかは、元のログからは断定できません。

## 対応

- 自作レシピの作成・仕上げを、Google公式料金表で無料枠が案内されている `gemini-3.5-flash-lite` へ分けました。外部抽出は既存のGemini 3.6 Flashです。Googleの契約・課金設定や秘密キーは変更していません。
- `ai_jobs.model` で利用回数を追跡し、各モデル20試行/直近24時間、合計40試行/直近24時間、合計5試行/分、利用者12試行/時に制限します。失敗も数え、一時障害の再試行は別の枠を予約できた時に1回だけ行います。429・設定不備・安全性による停止は再試行しません。Google側の実際の制限は別途適用されます。
- 上限到達時は再試行できる時刻の目安を日本時間で表示します。入力不足、混雑、利用上限、回答の途中切れ、不正形式を分けて扱います。キーやレシピ本文をログに書かず、失敗コードとリクエストIDを残します。
- エラーを成功と同じ緑色のチェック表示にしないよう修正しました。仕上げボタンの近くにエラーを残し、入力内容を保持します。
- 通信障害や混雑時には、端末内で空行・番号・余分な空白だけを整える操作を用意しました。「AI未使用」と明示して確認後に反映します。材料や分量の補完はしません。

## 検証

- パスタの実API検証：200で成功。タコ100g、オリーブオイル小さじ1、1人分と「規定より30秒短く」の条件を維持。
- 公開画面の「材料・分量・作り方をAIで仕上げる」からも、案の表示と反映まで成功。
- 作成・仕上げの実APIテスト：18項目成功。鶏むね・レモン・辛い調味料の除外・人数保持・豆腐150gと小さじ1の保持を検証。
- 回答の失敗分類・再試行・端末内整形：25項目成功。
- 検索・入力制限・下書き：21項目成功。
- 本番ビルド・型チェック・差分チェック：成功。
- DB変更後のアドバイザーに新たな指摘はありません。RLSと直接アクセスの拒否は維持。ローカルDBが起動していないためCLIのローカル履歴照会は接続不可でしたが、リモートの適用履歴と実データのモデル別集計を確認しました。マイグレーションのファイル名をリモートの適用済み版と一致させました。

利用者のレシピを公開したり、Solana送金を行ったりしていません。

公式資料：https://ai.google.dev/gemini-api/docs/pricing#gemini-3.5-flash-lite 、https://ai.google.dev/gemini-api/docs/rate-limits
